# 工业智能语义基座 · 贡献归属核对

用途：在继续改作品集前，先把“产品方向、平台既有机制、我的交互设计”分开。只有确认属于我的判断，才使用“我决定 / 我提出 / 我主导”；其余统一写成“产品定方向，我负责交互落地”或“平台的设计”。

## A. 已确认属于我的核心贡献

### 1. 质量 Agent 整体交互重设计

- 原始状态：算法工程师先实现了能计算 Cpk、SPC、判异的 demo，但结果长、密、难以使用。
- 我的工作：吃透业务和功能后，重新设计整个 Agent 的人机交互。
- 已确认的具体设计：
  - 将一整块分析结果拆成可跳转的结构化报告；
  - 结论、计算与判异、异常解释、可能根因、处理措施、分析过程、调用记录、本体依据分层呈现；
  - 三栏可调布局：分析图表 / 知识图谱 / 对话；
  - 右侧提问驱动左侧图表变化，历史图表可回看，结果同步高亮图谱节点；
  - 均值图与极差图按查看习惯左右组织。
- 页面角色：第一核心故事，适合补 Before / After。

### 2. 操作类型：授权与提交模型

- 原始问题：权限需求模糊、分散，“谁能提交”和“什么条件下能提交”混在一起。
- 我的工作：梳理为两层结构：操作授权组 + 提交准则。
- 已确认的具体设计：增加命中用户预览，让抽象规则保存前能被核对。
- 页面角色：强支撑故事，可证明复杂 B 端规则与权限设计。

### 3. AI 图标库

- 我的工作：全程主导功能机制。
- 核心判断：图库检索是主路径，AI 生成只在图库失败时兜底，可用结果再上传入库。
- 推进过程：方案曾被认为无法实现；我借助 AI 拆解技术路径，并与前端验证后推动落地。
- 页面角色：第二核心故事，适合补真实设计分歧。

### 4. 项目初期 0→1 探索

- 我的工作：结合 Palantir 文档，以及 Figma Make、GPT、Claude Code 等工具完成竞品、功能与原型探索，交付初版。
- 页面角色：证明 AI Native 工作方式，但不要包装成整个平台的产品 ownership。

## B. 已确认不是我定方向，但我负责交互落地

### 1. 高风险 AI 结论需要可核验、可推翻

- 产品负责：人机边界和信任方向的基础定调。
- 我的工作：把方向落成工程师能够理解、查看和操作的界面。
- 禁止表述：“我定义了平台的人机协作范式”。

### 2. 使用国标解释质量异常

- 平台负责：用 GB/T 4091 / 判异规则作为判断依据。
- 我的工作：让标准、数据点和异常结论在界面中能够被看懂和核对。
- 页面角色：平台信任设计，不作为个人核心决策。

## C. 尚未确认归属

以下内容在核实前不使用第一人称 ownership：

### 1. 沙盘推演

- 属性覆盖使用结构化表单；
- 自动化步骤允许自然语言起草、结构化回显并经人工采纳。
- 待确认：这个差异化交互是谁最先提出？我是否发现并修正过原方案？

### 2. 本体链接类型

- 不同基数使用不同布局，让错误配置没有入口。
- 待确认：基数决定布局是产品规则、研发约束，还是我的交互方案？原方案是什么？

### 3. RID / 实体唯一编号

- 在实体详情中让人看到机器侧唯一编号。
- 待确认：显示 RID 是谁提出？用户是否真的依赖它核对 Agent 输出，还是作品集推演？

### 4. AI 管道生成器：字段作用域

- 输入框上方常驻当前可用字段，降低写出不存在字段的概率。
- 待确认：字段面板与输入端校验是谁提出？当前意图解析实际为正则，不能写成 LLM 防幻觉成果。

### 5. AI 管道生成器：画布作为事实源

- AI 生成节点提案，最终产物回到可编辑画布。
- 待确认：这是不是产品原始形态？我具体做了哪些交互设计或评审修正？

## D. 下一轮讨论只需回答的问题

对 C 区每项，按下面四问回答即可：

1. 最开始产品或研发给你的方案是什么？
2. 你觉得哪一点不合理，依据是什么？
3. 你提出或画出了什么不同方案？
4. 最终开发的是哪一版，有没有反馈或后续调整？

如果某项想不起来或确实不是你的判断，就诚实降级为平台能力，不必强行留下。

## E. 页面重构目标

- 主故事 1：质量 Agent Before / After；
- 主故事 2：AI 图标库“无法实现 → 拆路径 → 验证 → 落地”；
- 强支撑：操作授权组 + 提交准则；
- 其他已确认属于我的判断：合并为一组较短的证据；
- 平台既有机制：只为理解产品服务，不与个人贡献同权；
- 最终保留 3 条真正属于我的可迁移原则。
