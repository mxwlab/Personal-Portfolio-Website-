# 工业智能语义基座 · 真实界面取证清单

更新时间：2026-08-27

用途：用于重做个人作品集中的工业智能语义基座案例页。真实项目只读，不在该仓库内修改业务代码。

## 作品集故事线

页面不按产品菜单平铺，而按一条认知链展开：

1. 先说明平台如何把数据、工业语义和 Agent 连成一个系统。
2. 用质量 Agent 证明高风险 AI 结论如何被看懂、核验和追问。
3. 用沙盘证明结论如何在不影响真实生产的前提下被推演。
4. 用 AI 管道证明非技术用户如何把意图变成可检查的生产流程。
5. 用操作授权和本体配置证明智能应用背后有可治理的语义与权限地基。
6. 回到我的真实贡献：质量 Agent 交互重设计、操作授权结构、AI 图标库与 0→1 原型探索。

## 12 个候选真实界面与交互状态

### A. 平台全貌（1 张）

1. **新版侧栏信息架构**
   - 取景：完整左侧导航，展示发现 / 提案 / 历史，以及多模态集成、本体管理、本体智能、设置四组。
   - 价值：一眼建立平台体量和三层能力结构。
   - 当前状态：用户已提供新版设计截图，真实项目代码尚未更新；案例页可以将其标为“新版信息架构设计”，不能冒充已上线界面。

### B. 质量 Agent 主证据（4 张）

2. **工作台初始态**
   - 取景：左上分析板、左下知识图谱、右侧质量 Agent 的真实布局；保留可拖拽分隔关系。
   - 价值：说明用户不是给聊天框换皮，而是重构了一个多工作区协同界面。

3. **自然语言提问后的联动态**
   - 取景：右侧问题与回答、左侧过程概览或 Cpk 图表、下方图谱高亮同时出现。
   - 价值：证明“提问 → 分析 → 图谱证据”的跨面板反馈。

4. **SPC 图控与判异态**
   - 取景：均值图 X̄ 与极差图 R 并排，异常点或第 34 子组被标出，指标选择器可见。
   - 价值：展示工业分析密度，以及按用户习惯组织图表的具体设计。

5. **结构化分析报告态**
   - 取景：目录 + 章节 + 告警 + 键值 + 表格/状态列表中的 2–3 种块同时出现。
   - 价值：证明用户把算法输出从长文本拆成可跳转、可扫描、可核验的报告体系。

### C. 沙盘推演（2 张）

6. **推演输入态**
   - 取景：图谱画布、选中对象、属性覆盖配置、运行推演动作。
   - 价值：把“如果改变某个条件会怎样”变成可操作的输入界面。

7. **推演结果态**
   - 取景：状态变化后的图谱、受影响节点数、影响范围、相邻影响和结果摘要。
   - 价值：展示从模拟动作到影响解释的完整闭环。

### D. AI 管道生成器（3 张）

8. **数据集选择与画布初始态**
   - 取景：数据集/字段选择、X6 节点画布和 Agent 面板。
   - 价值：建立“用户意图必须落到真实字段和节点”的约束背景。

9. **Agent 意图确认态**
   - 取景：用户指令、Agent 识别出的操作、选中数据集字段、可编辑 SQL、确认/取消/重新生成。
   - 价值：证明 AI 不会直接改写事实源，人仍保留检查和确认权。

10. **运行与调试态**
    - 取景：完整管道、节点数据预览抽屉、可伸缩调试控制台、日志或 SQL 预览。
    - 价值：展示从生成到验证的生产级闭环，而不是只展示聊天结果。

### E. 治理地基（2 张）

11. **操作授权组 + 提交准则**
    - 取景：直接添加 / 从部门添加 / 从用户字段添加，以及固定权限阈或参数条件组；如果空间允许，加入命中用户预览。
    - 价值：这是用户可明确认领的结构化设计贡献，回答“谁能执行、什么条件下能提交”。

12. **对象类型配置 / 图标 / RID / 关系图**
    - 取景：对象基础信息与关系图，优先选择能同时看到图标配置和可核验标识的状态。
    - 价值：收束到智能应用背后的语义资产；若一个画面无法讲清，可将图标系统拆成局部放大图而不新增主截图。

## 脱敏规则

### 必须删除或替换

- 公司名称、Logo、组织/部门名称和能够反推出公司的品牌线索。
- 内部域名、IP、端口、环境名、服务器地址、接口基址和任何基础设施信息。
- 用户名、姓名、工号、邮箱、手机号、头像和真实人员列表。
- 数据源连接信息、数据库名、表名、账号、Token、Cookie、请求头和密钥。
- 未公开客户、工厂、产线、设备编号、供应商和项目代号。
- 浏览器地址栏、开发者工具、终端与系统通知中可能出现的本机或内部路径。

### 需要业务化改写

- 真实对象 ID、RID、批次号、工单号、节点 ID：保留格式逻辑，替换具体值。
- 数据集名、字段名、SQL、日志：保留结构和交互证据，改为通用轴承质量示例。
- 图谱节点与关系：保留对象类型和推演关系，统一改成虚构样例。
- 人员授权名单：使用“工艺工程师 A / 质量负责人 B”等虚构角色。
- 质量指标与日期：仅使用项目现有 Mock 或明确可公开的示例，不把目标值包装为实际成果。

### 可以保留

- 通用产品模块名称、交互结构和无敏感性的控件文案。
- GB/T 4091、Cpk、SPC 等公开标准与工业质量概念。
- 经过确认的技术栈和设计职责边界。
- 项目已有的本地 Mock 数据，但截图前仍需逐项检查是否混入真实接口回包。

## 截图执行标准

- 桌面主图统一在同一浏览器宽度截取，建议 1440 × 900 或 1512 × 982。
- 关闭书签栏、下载条、系统通知和无关标签页。
- 每张图先进入稳定状态，避免 loading、tooltip、光标和临时 toast 遮挡核心内容。
- 同一流程截图保持同一窗口尺寸与面板宽度，便于作品集做连续分镜。
- 原始截图单独保存；脱敏版另存，不覆盖原图。
- 作品集只使用脱敏版，且不提交真实项目的环境文件或接口数据。
