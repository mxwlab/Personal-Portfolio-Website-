平台背景

让分散的工业数据与知识，成为 AI 能理解的业务上下文。

工业数据分散在不同系统中，同一个对象可能有不同名称与口径，业务知识也难以直接用于计算和分析。AI 要理解这些数据，需要先明确它们代表什么，以及彼此有什么关系。

工业智能语义基座通过数据接入与处理、本体建模和智能应用，将数据、对象与业务关系组织起来，为不同工业场景提供共同基础。轴承质量分析是首个落地场景。

01

质量 Agent

围绕检测异常，查看分析结论、图表与业务关系。

把连续分析，变成可核对的工作台。

算法工程师先做出了能够计算质量指标、识别异常的 demo。分析结果已经存在，但内容密集，对用户不够友好。我先理解业务与功能，再重新设计整个 Agent 的人机交互。

报告中的解释、图表里的数据和业务对象之间的关系，需要让工程师能够来回核对。

让结论、证据与追问接得上。

01

拆开报告，让结论有路可查。

我将结论、计算与判异、异常解释、可能根因和处理措施等内容拆成可跳转的段落，用目录帮助用户先找到重点，再深入依据。

02

连接三栏，让追问保留上下文。

我设计左侧图表、中间业务图谱、右侧对话的结构。提问带动图表变化，相关节点同步高亮；历史图表保留回看入口，三栏空间可以调整。

03

并列图表，让不同依据一起被看见。

均值图与极差图按查看习惯并列呈现。我将平台既定的判异依据、数据点和分析结论组织到界面中，方便工程师核验。

交互演示

提问之后，三栏一起回应。

向右侧质量 Agent 提出判异问题后，报告导航与关键摘要给出结论和依据；左侧均值图 X̄ 与极差图 R 画出控制限与异常点，底部业务图谱同步高亮相关对象。图表、业务关系与对话在同一屏里相互指认，工程师可以顺着任一处来回核对。

02

沙盘推演

围绕业务对象，配置属性变化与条件规则，编排推演计划。

让复杂规则，成为能检查的推演计划。

沙盘面向“改变某个条件后会怎样”的任务。用户既需要修改具体属性，也需要编排条件、动作和执行顺序。

逐项填写对象、条件和动作比较繁琐；只用自然语言，又容易把复杂规则表达得不够明确。我参与提出手动配置与自然语言起草双入口，让快速表达与精确控制配合。

两种表达方式，汇入同一份计划。

手动配置 / 精确控制

将触发条件和执行动作分别配置，逐项指定对象、属性与值，提交到步骤计划。

自然语言 / 快速起草

围绕已选对象描述需求，生成建议后分别查看条件与动作，采纳后进入步骤计划。

起草、采纳、运行，各有明确的位置。

01

生成建议

显示条件与执行动作

02

审阅采纳

决定是否纳入计划

03

编排步骤

检查内容、编辑与排序

04

仿真运行

审阅整份计划后发起

查看手动配置与自然语言起草＋

例如，“当质量状态为 FAIL 时，将需要复核设为 true”。自然语言建议将条件与动作分别回显，并保留待审阅、已采纳、已弃用状态。

手动配置同样进入左侧计划列表。直接改值的任务则由属性覆盖承担，对象、属性、原值与覆盖值并列呈现。

03

AI 管道

选择数据集，描述处理需求，并检查生成流程与中间数据。

让处理需求，与具体数据始终对应。

自然语言表达需求之后，用户仍需要明确这次处理哪些数据，以及每一步处理后的内容。我重点解决操作范围、字段引用和生成结果检查三个问题。

从表达需求，到检查结果。

01

操作前：明确当前处理哪些数据。

我区分“加入画布”和“选择本次输入”，通过节点已选状态与右侧输入标签，明确当前操作范围。完整流程保留在画布里，本次输入单独标明。

02

表达时：把可用字段放在手边。

为了帮助用户准确引用字段，我将可用字段放在输入区附近，让用户描述转换、连接或结合需求时，可以直接参照当前数据结构。

03

生成后：检查每一步的数据。

只有节点与连线，还不足以判断结果是否符合预期。我增加节点预览与中间数据检查入口，让用户查看字段类型与样本内容，同时保留画布和对话的上下文。

查看输入选择与节点数据预览＋

节点预览在底部展开数据表，保留画布与对话区域。用户既能查看处理经过了哪些步骤，也能进入具体节点查看数据。
