01 / OUTCOME

质量 Agent 已进入工厂使用。

质量 Agent 已在试点工厂的产线上使用，服务一线的工艺与质量工程师。一次异常排查从原来需要跨系统翻找记录，变成在一个工作区内看到结论与依据。

80→30单次排查耗时（分钟）
2–3覆盖产线（条）

30–50每月减少的排查工时（小时）

数据为项目期间按工程师排查流程估算，非系统实测。

02 / CONTEXT

给工业数据和 AI 一套共同的业务语言。

工业知识与 AI 之间隔着一层语义不确定：同一对象在不同系统里的名称和口径不一致，AI 难以准确理解，分析也就难以可信。

项目面对三个挑战：数据分散在不同系统、口径不一，难以协同；AI 不理解工业机理与业务语义，难以支撑决策；工业知识需要转化为可计算、可复用的数字资产。

目标是建设一套机器可理解、可执行的统一业务语义体系，相当于一本“工业数据字典”，让工业软件、AI 模型和数据系统说同一种“普通话”。

03 / SCENARIO

一次硬度异常，要跨两套系统核对 7 项信息。

首个落地场景是轴承质量分析。出现硬度异常时，工程师要在生产系统与质检系统之间逐项核对：同一零件、同一批次、检测时间、硬度标尺、适用规格、热处理记录、初检还是复检。任何一项对不上，结论就不可信。

面向工程师的是三个应用，连成一条任务链：先准备数据，再分析异常，最后比较处理方案。

04 / KEY JUDGEMENTS

三个关键判断。

  • 范围收敛：先跑通一条完整链路，再扩展。

    从整个平台收敛到“轴承硬度异常的初步排查”这一个场景，让三个应用先串成“数据准备 → 异常分析 → 方案比较”的闭环。

  • 人机分工：程序算，模型讲，工程师定。

    统计与判异由程序完成；模型负责理解问题、组织结果、承接追问；原因假设与下一步排查由工程师核实决定。

  • 可追溯：每个结论都能回到依据。

    计算结果与 AI 解释分开呈现；对象范围、数据一致性和结论边界写进验收标准。

建设顺序由团队讨论确定：先管道、再 Agent、最后沙盘，我参与梳理。数据没有接好、关联好，后面的分析就无从谈起。

05 / QUALITY AGENT

围绕一个异常问题，组织分析、追问与报告。

原有 Demo 已经具备分析能力，但解析过程、工具调用、计算过程与结论混在同一段回答里。工程师需要自己找重点，也不容易判断看完之后该做什么。

我把设计重点放在工程师的排查任务上：先呈现结论和关键依据，再按问题提供所需图表，支持继续追问和整理报告。

  • 报告按固定章节组织，每个结论都能找到依据。

    分析结果按章节、指标和表格组织，通过目录定位结论、指标与原因假设，并保留来源入口，方便逐项核对。

  • 计算结果与 AI 解释分开呈现。

    指标与判异结果独立呈现，AI 的原因分析明确标为“待核实假设”；生成报告时汇总已有结果并保留来源，避免把推测写成确定结论。

“可用”的标准不只是能回答，而是对象正确、数值准确、来源可查、结论不过界。验收围绕四类问题：分析范围是否正确且不擅自扩大；图表、报告和来源是否使用同一份数据；能否区分异常关联与根因；查询失败或任务取消后是否避免覆盖有效结果。项目期间完成了 8 轮评审、20 次样本核对。

06 / AI PIPELINE

把处理需求转成可检查的流程，再交给系统执行。

分散的生产与质检记录，需要合并、关联和字段转换后才能用于分析。人工配置要求操作者同时理解业务要求和数据结构。AI 辅助起草的价值，是让用户从逐项配置，转向审阅和修正一份具体方案。

  • 先看清方案如何改变数据，再决定是否执行。

    待确认的操作以预览形式与已应用的步骤区分；应用、保存与运行各自独立，用户确认的是具体处理要求，而不是笼统地点一次“继续”。

  • 保留精确修正的入口。

    自然语言适合表达要求；对能读懂处理逻辑的用户，保留在步骤内直接修改的入口，避免为调整一个字段反复改写问题。最终执行逻辑以可核对的规则为准。

07 / SANDBOX

在实际处理前，先验证一套规则会带来什么变化。

质量分析能帮助发现异常，但接下来采用什么处理办法，还需要验证：调整判定条件后，哪些记录会被重新分类，哪些保持不变？沙盘让工程师在不改动真实数据的情况下试运行，再判断方案是否符合预期。目前为原型阶段。

  • 分开“修改的对象”与“观察的对象”。

    需要调整属性的对象与需要观察结果的对象并不总是相同。把两者分开设置，运行前就能确定范围，运行后也能分清谁变了、谁没变。

  • 规则先审阅，再执行。

    手动配置与自然语言两种入口汇入同一份执行计划；自然语言先形成可审阅的提议，确认后才加入计划，再由用户主动启动。

  • 变化可见，依据可追溯。

    区分“假设已应用”与“运行后变化”，每次推演独立留存，方便回看当时的配置与结果。
