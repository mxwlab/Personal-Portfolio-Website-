02关键判断

CONTINUITY ≠ COPY EVERYTHING

连续性不是复制全部聊天，
而是交付下一步必需的状态。

01 / Scope

一个项目，一段独立对话

每个项目拥有独立身份和上下文边界，避免不同项目的信息混在一起。

02 / Handoff

可更新的最小交接状态

只保留当前目标、用户意图、约束、决定、开放问题和下一步承诺。

03 / Context

有限的最近对话

最近对话补充语气与现场信息，但不让无限增长的历史淹没当前任务。

04可信边界

Trust by design

能接住工作，也必须守住边界。

LOCAL

数据留在本机

没有云端服务和跨用户共享；每位用户运行自己的本地实例。

ISOLATED

项目隔离

只读取当前项目对应的交接与最近对话，其他项目保持不可见。

REVISIONED

并发不静默覆盖

交接状态使用版本检查，过期写入会明确冲突，而不是悄悄覆盖新决定。

RETENTION

原始内容定期脱敏

超过 30 天的事件正文被清除，同时保留必要的事件元数据。

FAIL CLOSED

无法生成上下文就停止

连续性失效时不会假装已经接上，而是阻止带着错误前提继续工作。

REVERSIBLE

接入可以安全撤销

支持按项目退出和完整卸载，默认保留用户数据，清除数据需要明确选择。

Evidence, not claims

真正的完成，是别人能装、能用，也能安全退出。

当前已验证 macOS + zsh 下的 Claude Code / Codex CLI 自动启动路径；桌面端采用辅助读取方式。它不假装已经解决云同步或多机协作，而是先把一个清晰、可信的本地闭环做完整。

我自己也是它的长期用户——每天在 Claude Code 与 Codex 之间切换时都在用它，用了一段时间，交接已经顺手到几乎无感。
